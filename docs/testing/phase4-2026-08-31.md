## Bugs demonstrated before fixing

The initial expanded tests reproduced three backend failures and three frontend
failures. Tests were kept and passed after these limited fixes:

| Demonstrated failure | Fix |
| --- | --- |
| Listing returned 1,000 of 1,003 distinct documents | Follow Qdrant scroll offsets until exhausted |
| Upload overwrote/deleted a pre-existing `temp_paper.pdf` file | Use an exclusive, server-owned temporary PDF path |
| Concurrent uploads named `same.pdf` shared a path and mixed content or failed cleanup | Same unique temporary-path fix isolates uploads |
| Whitespace-only question reached the API | Reject whitespace-only input in React |
| Repeated clicks while generation was pending sent duplicate requests | Track pending state and disable Ask until completion |
| Selecting the same file after a failed upload did not trigger retry | Reset the file input after each upload attempt |

The first backend test run also exposed an isolation mistake in the new test
harness: its dependency override did not cover factory functions that directly
access the repository singleton. The fixture was corrected; production DI was
not changed to satisfy the tests.

No changes were made to production chunking, embedding models, `k`/`fetch_k`,
metadata filter semantics, CrossEncoder scores/threshold/floor/top-N, generation
model/prompt, RAGAS definitions, or historical metrics/results. The temporary
loader `source` path now varies per upload; original `source_file`, page, and
chunk text are preserved. No Phase 3 artifact was rewritten.

## Remaining gaps and limits

- **Live grounded refusal:** the two real Groq checks are skipped. Prompt tests
  cannot guarantee that a hosted model follows the refusal rule. There is still
  no enforced backend refusal guard, and the API still accepts blank strings;
  the added whitespace protection is at the UI boundary only.
- **Remote Qdrant:** embedded Qdrant is exercised, including native MMR, but cloud
  credentials, payload-index creation, network recovery and ANN behavior are not.
- **Browser end-to-end:** React tests use jsdom and controlled fetch. Build/CORS
  tests do not replace a real browser-to-FastAPI-to-Groq test. CSS, accessibility,
  layout and browser-engine differences are outside this suite.
- **Evaluation recovery:** safety guards are tested; live retry/backoff/quota
  recovery is not. The optional verifier re-embedding branch for archived Answer
  Relevancy is not covered here; real RAGAS AR arithmetic and real cached
  embeddings are checked separately.
- **Legacy/unused modules:** legacy `evaluation/run_eval.py`, synthetic-corpus
  creation CLI, `evaluation/metrics/custom_metrics.py`, unused domain models and
  online logging placeholder remain untested. They are included in coverage.
- **Additional robustness:** no OCR, huge/hostile-PDF resource exhaustion,
  exhaustive PDF fuzzing, GPU parity, cross-process ingestion load, auth/security
  audit, or runtime validation of every frontend success-response schema.
- **Historical source hashes:** ingestion/listing fixes legitimately change two
  production file hashes. The existing strict Phase 3 verifier must be used with
  the original source snapshot for historical source matching. Its check was not
  weakened and old metadata was not edited.
